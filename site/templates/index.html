Rust crate · macOS and Linux · pre-1.0

Cage the commands your program runs on someone else’s behalf.

procage runs a child process under an OS sandbox: Seatbelt on macOS, without sandbox-exec, and Landlock, seccomp and namespaces on Linux. It is built for commands that run untrusted, adaptive code as your user, such as an LLM agent’s tool calls or a project’s build scripts.

Get started Read the threat model GitHub

Status: under development. The published 0.0.1 only reserves the name; the development version on main cages children on both systems. Do not rely on any release before 0.1.0 to contain a process.

Why procage

An agent that follows injected instructions, or a malicious build script, runs with your user id. It can read ~/.ssh, plant a git hook your shell later runs, register a launch agent, or keep a daemon alive after you thought it ended. procage is meant to keep that code away from your secrets, from files outside the paths you grant, from your terminal and session, and from persistence locations.

One policy, lowered per OS

You write a typed, deny-by-default policy once. procage lowers it to a Seatbelt profile or a Linux plan, and every construct is exact, an approximation you accept by name, or a typed capability gap.

Policies

Never silently weaker

A host that cannot enforce part of a policy refuses the cage and lists every gap. Cage::fit relaxes only what you name and tells you what would lift each relaxation.

Fitting a policy

Know what was denied, and why

Instead of a bare “Operation not permitted”, a reporting cage lists each denied operation with the process, the path and the rule behind it (not granted, hidden, protected, a hard-deny class), live or after the exit: every denial on macOS, every refused system call on Linux.

Violations

A hard-deny tier in every policy

Secrets, trust-handoff files such as git hooks and shell startup files, persistence locations, privilege changes and more are denied last, in every policy, and waivable only by class name.

Hard-deny classes

Lifetime and hygiene

Inherited descriptors are closed, secret-looking variables dropped, the terminal kept out of reach, and every process the run started is killed when the run ends, double-forked daemons included.

Lifetime and hygiene

Escape classes with canaries

Every known escape class has a stable id and a status in the threat model. A class is marked handled only when caged canaries on a real kernel show the refusal.

Threat model

No helper binaries

The library applies the sandbox in the forked child with system calls only. Or a small helper becomes the caged command with Cage::exec, for code that starts and kills processes itself.

Running helpers

Platforms

procage measures what the host offers and never falls back to running unsandboxed. What a Linux host gets depends on its tier and Landlock ABI.

What it is not

An OS sandbox reduces the risk from adaptive same-user code; it does not remove it. The kernel and OS services stay reachable, and a bug in them is an escape. When that is unacceptable, use a microVM, or a microVM with procage inside it for finer-grained policy.

Open today: a hard link made before the run is not reported (R-08), and on macOS a caged child can read your other processes’ arguments and environment (R-25). The threat model lists every class and its status.
